
### Задача 1. Система учёта складских запасов (1,5 часа)

**Постановка задачи:** Необходимо создать базу данных для небольшого склада. На складе хранятся товары, которые поставляются разными поставщиками. Каждый товар имеет уникальный артикул, название, единицу измерения и текущую цену. Товар может поставляться несколькими поставщиками, при этом цена поставки может отличаться. Необходимо отслеживать остатки товара на складе и фиксировать все операции прихода и расхода.

**Задания для выполнения:**

1.  **Создание БД и таблиц:** Напишите скрипт `CREATE DATABASE WarehouseDB` и создайте все таблицы с необходимыми ограничениями (`PRIMARY KEY`, `FOREIGN KEY`, `CHECK` для типа операции и положительного количества).
2.  **Запросы различного формата:**
    - Напишите запрос с `INNER JOIN`, который выводит список всех товаров и их поставщиков с ценами поставки.
    - Напишите запрос с `LEFT JOIN`, который показывает все товары, даже если они ещё ни разу не поставлялись.
    - Используйте `GROUP BY` и `HAVING`, чтобы найти товары, средняя цена поставки которых превышает 1000 рублей.
3.  **Представление (View):** Создайте представление `vw_CurrentStock`, которое рассчитывает текущий остаток по каждому товару (Сумма приходов минус сумма расходов).
4.  **Функция:** Создайте скалярную функцию `fn_GetStockByProduct(@ProductID INT)`, которая возвращает текущий остаток для конкретного товара.
5.  **Процедура:** Создайте хранимую процедуру `sp_AddStockOperation`, которая принимает ID товара, тип операции и количество. Процедура должна проверять, не пытается ли пользователь списать больше, чем есть на складе (если тип «Расход»). Если попытка списания превышает остаток, процедура должна вывести ошибку.
6.  **Триггер:** Создайте триггер `TR_StockOperations_UpdatePrice` на таблицу `StockOperations` `AFTER INSERT`. Если происходит приход товара, и цена поставки в этот день выше, чем `BasePrice` в таблице `Products`, триггер должен обновить `BasePrice` на новую цену.
7.  **Оконная функция:** Напишите запрос, который выводит все операции, но добавляет столбец с накопительным итогом количества товара (Running Total) для каждого товара отдельно, упорядоченный по дате.
8.  **Транзакция:** Напишите блок `BEGIN TRANSACTION`, который добавляет новую операцию прихода и одновременно обновляет цену в таблице `Products`. Сымитируйте ошибку (например, деление на ноль или неверный ID), чтобы проверить откат транзакции (`ROLLBACK`) в блоке `TRY...CATCH`.
9.  **Курсор:** Напишите курсор, который проходит по всем товарам с остатком ниже 10 единиц и выводит сообщение `PRINT 'Товар ' + ProductName + ' заканчивается!'`.

### Задача 2. Библиотечная система (1,5 часа)

**Постановка задачи:** Библиотека выдаёт книги читателям. У каждой книги есть автор и жанр. Один автор может написать много книг. Читатель может взять несколько книг, но у каждой выдачи есть дата возврата. Нужно контролировать, чтобы читатель не взял книгу, если она уже на руках.


**Задания для выполнения:**

1.  **Создание БД и таблиц:** Создайте `LibraryDB` и таблицы. Убедитесь, что `LibraryCardNumber` уникален (`UNIQUE`).
2.  **Запросы:**
    - Выведите список книг с именами авторов и названиями жанров (три таблицы через `JOIN`).
    - Найдите читателей, которые взяли более 3 книг за всё время (используйте `GROUP BY` и `HAVING`).
    - Используйте `UNION`, чтобы вывести список «Книги, которые сейчас на руках» и «Книги, которые никогда не выдавались».
3.  **Представление:** Создайте представление `vw_OverdueBooks`, которое показывает книги, невозвращённые в течение 30 дней с момента выдачи (используйте `DATEDIFF`).
4.  **Функция:** Создайте табличную функцию `fn_GetBooksByAuthor(@AuthorName NVARCHAR(100))`, которая возвращает таблицу со списком книг этого автора.
5.  **Процедура:** Создайте процедуру `sp_IssueBook(@BookID INT, @ReaderID INT)`. Процедура должна проверить, не выдана ли уже эта книга (проверка по `ReturnDate IS NULL`). Если книга свободна, она добавляет запись в `Loans`.
6.  **Триггер:** Создайте `INSTEAD OF INSERT` триггер на таблицу `Loans`, который проверяет, что `LoanDate` не может быть в будущем. Если дата корректна, триггер выполняет вставку.
7.  **Оконная функция:** Для каждой книги выведите количество раз, которое она была выдана, и ранг книги по популярности (используйте `RANK()` или `DENSE_RANK()`).
8.  **Транзакция:** Напишите процедуру с транзакцией, которая принимает список книг (через параметр) и пытается выдать их читателю. Если хотя бы одна книга занята, вся выдача отменяется.
9.  **Курсор:** Напишите курсор, который проходит по всем читателям и для каждого выводит количество книг, которые он должен вернуть (где `ReturnDate` всё ещё `NULL`).

### Задача 3. Управление ИТ-проектами (1,5 часа)

**Постановка задачи:** Компания ведёт проекты. В проекте участвуют сотрудники с разными ролями (разработчик, тестировщик, менеджер). Один сотрудник может участвовать в разных проектах. Необходимо учитывать отработанные часы по каждому сотруднику в рамках проекта.

**Задания для выполнения:**

1.  **Создание БД и таблиц:** Создайте `ProjectDB` и таблицы. Убедитесь, что `HoursWorked` имеет ограничение `CHECK (HoursWorked > 0 AND HoursWorked <= 24)`.
2.  **Запросы:**
    - Выведите список проектов и общее количество часов, отработанных по каждому проекту.
    - Найдите сотрудников, которые работали над проектами в двух разных ролях (используйте `EXISTS` или `GROUP BY` с `HAVING COUNT(DISTINCT RoleID) > 1`).
    - Используйте `CASE`, чтобы вывести статус проекта: «Завершён», «В процессе», «Не начат» на основе текущей даты и дат проекта.
3.  **Представление:** Создайте представление `vw_ProjectCost`, которое рассчитывает стоимость каждого проекта (Сумма `HoursWorked * HourlyRate`).
4.  **Функция:** Создайте скалярную функцию `fn_GetEmployeeTotalHours(@EmployeeID INT)`, которая возвращает общее количество часов, отработанных сотрудником за всё время.
5.  **Процедура:** Создайте процедуру `sp_LogTime`, которая принимает `AssignmentID`, `WorkDate` и `HoursWorked`. Процедура должна проверять, что `WorkDate` находится в пределах дат проекта (через `JOIN` к `Projects`).
6.  **Триггер:** Создайте триггер `TR_TimeLogs_Update`, который при обновлении `HoursWorked` (если новое значение меньше старого) записывает информацию об изменении в отдельную таблицу аудита `TimeLogsAudit`.
7.  **Оконная функция:** Для каждого сотрудника выведите его суммарные часы и процент от общего количества часов по всем сотрудникам (используйте `SUM() OVER()`).
8.  **Транзакция:** Напишите транзакцию, которая переводит сотрудника с одной роли на другую (обновляет `RoleID` в `ProjectAssignments`), и одновременно повышает его `HourlyRate` на 10%. Используйте `SAVE TRANSACTION`, чтобы при ошибке на втором шаге можно было откатиться только к точке сохранения.
9.  **Курсор:** Напишите курсор, который проходит по всем проектам, и если суммарная стоимость проекта (по часам) превышает бюджет (добавьте поле `Budget` в таблицу `Projects`), выводит предупреждение.

### Задача 4. Система онлайн-курсов (1,5 часа)

**Постановка задачи:** Платформа онлайн-курсов. Студенты записываются на курсы. Курс состоит из уроков. Студент может пройти урок и получить оценку. Необходимо отслеживать прогресс студентов.


**Задания для выполнения:**

1.  **Создание БД и таблиц:** Создайте `OnlineCoursesDB`. Обратите внимание на связь `LessonCompletions` с `Enrollments`, а не напрямую со `Students`, чтобы избежать избыточности.
2.  **Запросы:**
    - Выведите список студентов и количество курсов, на которые они записаны.
    - Найдите курсы, на которые записалось больше всего студентов (используйте `TOP 1 WITH TIES`).
    - Выведите средний балл по каждому курсу (через цепочку `JOIN` к `LessonCompletions`).
3.  **Представление:** Создайте представление `vw_StudentProgress`, которое для каждой записи на курс (`EnrollmentID`) показывает процент завершённых уроков (Количество завершённых / Общее количество уроков в курсе * 100).
4.  **Функция:** Создайте табличную функцию `fn_GetStudentCourses(@StudentID INT)`, которая возвращает список курсов и прогресс по ним для конкретного студента.
5.  **Процедура:** Создайте процедуру `sp_CompleteLesson(@EnrollmentID INT, @LessonID INT, @Score INT)`. Процедура должна проверять, что `Score` от 0 до 100, и что этот урок ещё не был завершён в рамках данной записи на курс.
6.  **Триггер:** Создайте триггер `TR_LessonCompletions_Validate`, который при вставке проверяет, что студент записан на курс, к которому относится урок (через `EnrollmentID` и `LessonID`).
7.  **Оконная функция:** Для каждого студента выведите его оценки по урокам и разницу между его оценкой и средней оценкой по этому же уроку среди всех студентов (`Score - AVG(Score) OVER(PARTITION BY LessonID)`).
8.  **Транзакция:** Напишите транзакцию, которая записывает студента на курс и сразу же отмечает первый урок как пройденный с оценкой 100. Если на каком-то этапе происходит ошибка (например, дубликат записи), транзакция откатывается.
9.  **Курсор:** Напишите курсор, который проходит по всем курсам и выводит название курса и количество студентов, которые завершили все уроки этого курса (100% прогресс).

### Задача 5. Банковские операции (1,5 часа)

**Постановка задачи:** Упрощённая банковская система. Есть клиенты, счета и транзакции. Счёт может быть открыт в разных валютах. Необходимо контролировать баланс и фиксировать переводы.


**Задания для выполнения:**

1.  **Создание БД и таблиц:** Создайте `BankDB`. Убедитесь, что `Balance` не может быть отрицательным (через `CHECK`), но учтите, что для кредитных продуктов это правило может отличаться — в данной задаче баланс всегда >= 0.
2.  **Запросы:**
    - Выведите список клиентов и общую сумму их балансов в рублях (используйте `JOIN` и `CASE` для конвертации, если курсы валют заданы в отдельной таблице, или просто просуммируйте, если все счета в одной валюте).
    - Найдите счета, по которым не было транзакций за последние 30 дней.
    - Используйте `EXCEPT`, чтобы найти клиентов, у которых есть счёт, но нет ни одной транзакции.
3.  **Представление:** Создайте представление `vw_AccountStatement`, которое показывает для каждого счёта все транзакции с нарастающим итогом (баланс после каждой операции).
4.  **Функция:** Создайте скалярную функцию `fn_GetBalance(@AccountID INT)`, которая возвращает текущий баланс счёта (рассчитывается как сумма всех кредитовых операций минус сумма дебетовых, либо берётся из поля `Balance`, если оно поддерживается в актуальном состоянии).
5.  **Процедура:** Создайте процедуру `sp_TransferMoney(@FromAccountID INT, @ToAccountID INT, @Amount DECIMAL(18,2))`. Процедура должна:
    - Проверить, что на счету отправителя достаточно средств.
    - Снять сумму со счёта отправителя (Debit).
    - Зачислить сумму на счёт получателя (Credit).
    - Выполнить всё в рамках одной транзакции с обработкой ошибок.
6.  **Триггер:** Создайте триггер `TR_Transactions_UpdateBalance` на таблицу `Transactions` `AFTER INSERT`. Триггер должен автоматически обновлять поле `Balance` в таблице `Accounts` в зависимости от типа транзакции.
7.  **Оконная функция:** Для каждого клиента выведите его счета и ранг счёта по балансу внутри клиента (используйте `ROW_NUMBER() OVER(PARTITION BY ClientID ORDER BY Balance DESC)`).
8.  **Транзакция:** Напишите сценарий, который имитирует сбой при переводе денег (например, после списания со счёта отправителя происходит ошибка при зачислении). Убедитесь, что благодаря транзакции деньги не «исчезнут».
9.  **Курсор:** Напишите курсор, который проходит по всем клиентам и для каждого выводит сообщение, если суммарный баланс по всем его счетам превышает 1 000 000 (в пересчёте на одну валюту).

- При написании процедур и триггеров используйте `TRY...CATCH` для обработки ошибок.
- Для курсоров не забывайте про `CLOSE` и `DEALLOCATE`.
- Проверяйте работу триггеров, специально вставляя некорректные данные.
