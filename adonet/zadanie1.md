**Цель:** научиться открывать соединение и читать свойства.

**Задание:**

### Задача 23. Своя процедура с OUTPUT ⭐⭐⭐⭐

**Цель:** научиться создавать и вызывать процедуры «на лету».

**Задание:**
1. Через `ExecuteNonQuery` создайте процедуру `Task23_GetStats`:
   ```sql
   CREATE OR ALTER PROCEDURE dbo.Task23_GetStats
       @minAge INT,
       @count INT OUTPUT,
       @avgAge DECIMAL(5,2) OUTPUT
   AS
   BEGIN
       SET NOCOUNT ON;
       SELECT @count = COUNT(*), @avgAge = ISNULL(AVG(CAST(Age AS DECIMAL(5,2))), 0)
       FROM Users WHERE Age >= @minAge;
   END
   ```
2. Вызовите её через `SqlCommand` с `CommandType.StoredProcedure` и `@minAge = 20`.
3. Выведите `@count` и `@avgAge`.
4. Вызовите с `@minAge = 999` — убедитесь, что `@count = 0`, `@avgAge = 0` (не `DBNull`).
5. В конце удалите процедуру через `DROP PROCEDURE`.

**Использовать:** разделы 10.1, 10.2.
**Подсказка:** `ISNULL` в процедуре гарантирует `0` вместо `NULL` — это упрощает чтение на клиенте. Без `ISNULL` пришлось бы проверять `DBNull`.

### Задача 25. Импорт CSV в Users с отчётом ⭐⭐⭐⭐⭐

**Цель:** финальная задача — полный цикл: чтение файла → валидация → параметризованная вставка → отчёт.

**Задание:**
1. Создайте файл `users.csv` в формате:
   ```
   Name,Age,Email
   Иван,30,ivan@example.com
   Мария,25,-
   Пётр,abc,petr@example.com
   Ольга,40,olga@example.com
   ```
2. Напишите программу, которая:
   - Читает файл построчно (пропуская заголовок).
   - Для каждой строки валидирует: `Name` не пустое, `Age` — целое от 1 до 150, `Email` либо корректен, либо `-` → NULL.
   - Валидные строки вставляет через параметризованный `INSERT ... OUTPUT INSERTED.Id`.
   - Невалидные — пропускает с записью причины.
3. В конце:
   - Выведите отчёт: сколько строк обработано, вставлено, пропущено, с причинами.
   - Через `ExecuteScalar` получите `COUNT(*)` до и после — разница должна совпадать с числом вставленных.
4. Дополнительно: реализуйте «откат» — удалите всех пользователей, вставленных в этой задаче (по списку `Id`), через один параметризованный `DELETE ... WHERE Id IN (@p0, @p1, ...)`. Убедитесь, что количество вернулось к исходному.

**Требования:**
- Все вставки — через `SqlParameter`, без конкатенации SQL.
- Одна `SqlConnection` на всю операцию вставки.
- Отчёт — в консоль, аккуратно отформатированный.

**Использовать:** разделы 7.1, 7.2, 8.x, 9.2, 9.3.
**Подсказка:** для валидации email достаточно `MailAddress.TryCreate(email, out _)`. Для «откатa» собирайте `List<int>` вставленных `Id` — потом сгенерируйте `@p0..@pN` по образцу задачи 19.
