
## Часть 1. Задачи для отработки (20 штук, от простого к сложному)

### Уровень 1: Базовые операции с DataTable

1. Создайте DataTable `Cities` с полями `Id` (int) и `Name` (string). Добавьте 3 города и выведите их в цикле.
2. Создайте DataTable `Books` с полями `Title` (string), `Author` (string), `Year` (int). Добавьте 4 книги. Используйте `Select("Year > 2000")` и выведите результат.
3. В DataTable из задачи 2 измените год у первой книги на 2020. Выведите измененное значение.
4. Создайте DataTable и добавьте строку через `NewRow()`, а затем еще две — через `Rows.Add(params object[])`. Выведите `Rows.Count`.
5. Удалите строку из DataTable через метод `Delete()`. Проверьте, что `Rows.Count` уменьшился, но строка остается в состоянии `Deleted`.

### Уровень 2: DataAdapter и загрузка данных

6. Загрузите все строки таблицы `Categories` в DataTable через `SqlDataAdapter`. Выведите названия категорий.
7. Загрузите товары с `Stock > 20` в DataTable. Выведите `ProductName` и `Stock`.
8. Загрузите товары, отсортированные по `Price DESC`, в DataTable. Проверьте, что первая строка — самый дорогой товар.
9. Загрузите в один DataTable результат запроса с `JOIN` (Products + Categories), включив `CategoryName`. Выведите первые 3 строки.
10. Используя `SqlDataAdapter`, загрузите только те товары, у которых `CategoryID = 2`. Затем в памяти измените `Price` первого товара и выведите его. Не сохраняйте в БД.

### Уровень 3: DataSet и связи

11. Создайте пустой DataSet. Загрузите в него две таблицы: `Categories` и `Products` (с разными именами в DataSet). Выведите `Tables.Count`.
12. Создайте DataRelation между таблицами из задачи 11. Для первой категории выведите все её товары через `GetChildRows`.
13. Для первого товара из DataSet задачи 12 найдите родительскую категорию через `GetParentRow`.
14. Загрузите три таблицы в один DataSet (Categories, Products, и любую третью, созданную вручную). Выведите имена всех таблиц в DataSet.
15. Создайте DataRelation с именем `"CatProd"`. Попробуйте получить дочерние строки по имени связи. Убедитесь, что имя совпадает.

### Уровень 4: Изменение данных и Update

16. Загрузите товары в DataTable. Измените `Price` у двух товаров. Выведите `RowState` каждой измененной строки (`Modified`).
17. Загрузите товары, добавьте новую строку. Выведите `RowState` новой строки (`Added`). Не сохраняйте в БД.
18. Загрузите товары с `CommandBuilder`. Удалите строку, вызовите `Update()`. Проверьте в SQL Server Management Studio, что строка исчезла.
19. Загрузите товары, измените цену, вызовите `Update()`. Затем загрузите данные заново и убедитесь, что изменение сохранилось.
20. **Сложная задача:** Загрузите Categories и Products в DataSet со связью. Измените цену товара в дочерней таблице. Вызовите `Update()` только для таблицы Products (создав для неё отдельный адаптер с CommandBuilder). Убедитесь, что изменение попало в БД, а Categories не затронута.

## Комплексная задача 1. Мини-CRM: аналитика продаж по категориям с сохранением отчёта

**Условие:**

В базе `ShopDB` есть таблицы `Categories` и `Products`. Требуется:

1. Загрузить обе таблицы в один `DataSet` через `SqlDataAdapter`.
2. Создать `DataRelation` между ними.
3. Вычислить для каждой категории:
   - количество товаров;
   - суммарную стоимость запасов (`Price * Stock`);
   - среднюю цену товара.
4. Поместить результаты в **новую** `DataTable` (`CategoryReport`), созданную вручную, и добавить её в тот же `DataSet`.
5. Применить к товарам **скидку 5%** для категории «Электроника» (изменение только в памяти).
6. Вывести отчёт в консоль с выравниванием.
7. Сохранить отчёт в отдельную таблицу `CategoryReport` в БД (создать её через `SqlCommand`, затем залить данные через `SqlDataAdapter.Update` с `CommandBuilder`).

**Подсказки:**
- Для шага 7 потребуется `FillSchema`, чтобы `CommandBuilder` «увидел» структуру пустой таблицы.
- `GetChildRows("CatProd")` даёт товары категории.
- Не забудьте про защиту от деления на ноль при подсчёте средней цены.

## Комплексная задача 2. Синхронизация цен: сравнение «старой» и «новой» версий DataTable

**Условие:**

1. Загрузите товары в `DataTable` (`originalTable`) через `DataAdapter` — это «снимок на момент старта».
2. Сделайте копию через `DataTable.Copy()` — `workingTable`.
3. В `workingTable`:
   - всем товарам с `Stock < 10` поднимите цену на 15%;
   - добавьте новый товар «Powerbank» (категория 1, цена 2500, склад 20);
   - удалите товар «Футболка».
4. Используя `GetChanges()` и `DataTable.GetChanges(DataRowState)`, получите:
   - только добавленные строки;
   - только изменённые строки;
   - только удалённые строки.
5. Сформируйте «человеческий» отчёт об изменениях (что было → что стало) для каждой категории изменений, включая старые значения через `DataRowVersion.Original` и новые через `DataRowVersion.Current`.
6. Отправьте изменения в БД через `DataAdapter.Update()` (используя `SqlCommandBuilder`).
7. Загрузите данные заново и убедитесь, что все три типа изменений применились.

**Подсказки:**
- У удалённых строк `Current`-версия недоступна — обращайтесь к `DataRowVersion.Original`.
- `Copy()` создаёт копию с `RowState = Unchanged` у всех строк.
- Передавайте в `Update()` именно `GetChanges()`, а не весь `workingTable`.

## Комплексная задача 3. Импорт из «внешнего источника» с валидацией и транзакцией

**Условие:**

Представьте, что вам пришел CSV-файл (или список) с новыми товарами:

```
ProductName,CategoryName,Price,Stock
"Монитор 27"",Электроника,18999,10"
"Роман ""Мастер и Маргарита""",Книги,799,30"
"Кроссовки",Одежда,4500,25"
"Мышь беспроводная",Электроника,1599,50"
"Странный товар",НесуществующаяКатегория,1000,5
```

Требуется:

1. Загрузить `Categories` и `Products` в `DataSet` (с `DataRelation`).
2. Пройти по «импортируемому» списку (захардкодим как массив строк) и для каждой записи:
   - проверить, что `CategoryName` существует в `Categories` (иначе — пропустить с сообщением об ошибке);
   - создать `DataRow` в `Products`, подставив правильный `CategoryID`;
   - добавить строку в `DataSet`.
3. Выполнить **все** вставки в БД через `DataAdapter.Update()`, но **в одной транзакции**: если хотя бы одна вставка упадёт — откатить всё.
4. После `Update()` вывести итоговое содержимое `Products` из БД с названием категории (через `JOIN`).

**Подсказки:**
- Для валидации категории используйте `DataTable.Select` по имени (не забывайте экранировать апострофы).
- Для транзакции: `SqlTransaction` + назначение `.Transaction` **каждой** команде адаптера (включая сгенерированные `CommandBuilder`).
- Отправляйте в `Update()` только `GetChanges(DataRowState.Added)`.
- «Плохая» запись (несуществующая категория) должна быть пропущена, а не уронить весь импорт — она не попадает в DataSet.
