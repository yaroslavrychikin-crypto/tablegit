
## Структура каждого билета (общая для всех)

В каждом билете студент должен выполнить **8 этапов**:

1. **Постановка задачи** — прочитать описание предметной области.
2. **Проектирование в 3НФ** — обосновать, почему схема в 3НФ, нарисовать/описать таблицы.
3. **Создание БД и таблиц** — `CREATE DATABASE`, `CREATE TABLE` со всеми ограничениями (`PK`, `FK`, `CHECK`, `DEFAULT`, `UNIQUE`), заполнение тестовыми данными.
4. **Запросы** — `SELECT` с `WHERE`/`ORDER BY`, `INNER JOIN`, `LEFT JOIN`, `GROUP BY` + `HAVING`, подзапрос.
5. **Представление и функции** — одно `VIEW`, одна скалярная функция, одна табличная функция.
6. **Процедуры** — простая процедура и процедура с проверкой бизнес-правила.
7. **Триггеры** — `AFTER UPDATE` (логирование) и `INSTEAD OF` (запрет операции).
8. **Оконная функция, транзакция, курсор** — `RANK()`/`SUM() OVER()`, транзакция с `TRY...CATCH`, курсор с `PRINT`.

## Билет 1. Библиотека

**Предметная область:** Библиотека выдаёт книги читателям. У книги есть автор и жанр. Читатель может взять несколько книг; у каждой выдачи есть дата возврата.

**Таблицы (минимум):** `Authors`, `Genres`, `Books`, `Readers`, `Loans`.

**Обязательные объекты:**
- Запросы: книги с авторами (JOIN), читатели без выдач (LEFT JOIN), жанры с числом книг (GROUP BY + HAVING).
- `vw_ActiveLoans` — книги, которые сейчас на руках (дата возврата `NULL`).
- `fn_ReaderLoansCount(@ReaderID)` — количество выдач читателя.
- `fn_BooksByGenre(@GenreID)` — таблица книг жанра.
- `sp_IssueBook(@BookID, @ReaderID)` — выдать книгу, если она свободна.
- `sp_ReturnBook(@LoanID)` — вернуть книгу с проверкой, что она ещё не возвращена.
- `TR_Loans_LogReturn` — AFTER UPDATE, при заполнении `ReturnDate` выводит `SELECT` с информацией о возврате.
- `TR_Loans_PreventDoubleIssue` — INSTEAD OF INSERT, запрещает выдать уже занятую книгу.
- Оконная: `RANK()` книг по популярности (число выдач).
- Транзакция с `TRY...CATCH`: выдача книги + запись в лог; при ошибке — `ROLLBACK`.
- Курсор: читатели с более чем 3 активными выдачами — `PRINT` предупреждение.

## Билет 2. Склад

**Предметная область:** Склад хранит товары от разных поставщиков. Товар может поставляться несколькими поставщиками с разными ценами. Фиксируются приходы и расходы.

**Таблицы (минимум):** `Suppliers`, `Products`, `SupplierProducts`, `StockOperations`.

**Обязательные объекты:**
- Запросы: товары + поставщики (JOIN), товары без поставок (LEFT JOIN), товары со средней ценой поставки > 1000 (GROUP BY + HAVING), подзапрос — товары дороже средней `BasePrice`.
- `vw_CurrentStock` — текущий остаток по каждому товару.
- `fn_GetStockByProduct(@ProductID)` — остаток товара.
- `fn_ProductsBySupplier(@SupplierID)` — таблица товаров поставщика.
- `sp_AddStockOperation(@ProductID, @OperationType, @Quantity, @SupplierID)` — добавить операцию с проверкой остатка для расхода.
- `sp_GetLowStock(@Threshold INT)` — вывести товары с остатком ниже порога.
- `TR_StockOperations_UpdatePrice` — AFTER INSERT, при приходе с ценой выше `BasePrice` обновляет `BasePrice`.
- `TR_StockOperations_PreventNegative` — INSTEAD OF INSERT, запрещает расход, превышающий остаток.
- Оконная: накопительный итог количества по каждому товару (`SUM() OVER(PARTITION BY ...)`).
- Транзакция с `TRY...CATCH`: приход + обновление цены; при ошибке — `ROLLBACK`.
- Курсор: товары с остатком < 10 — `PRINT` предупреждение.

## Билет 3. Онлайн-курсы

**Предметная область:** Платформа курсов. Студенты записываются на курсы, курсы состоят из уроков, студенты проходят уроки и получают оценки.

**Таблицы (минимум):** `Students`, `Courses`, `Lessons`, `Enrollments`, `LessonCompletions`.

**Обязательные объекты:**
- Запросы: студенты + число курсов (LEFT JOIN + COUNT), курсы + средний балл (JOIN + AVG), курсы с более чем 2 студентами (GROUP BY + HAVING), подзапрос — студенты, записанные на самый дорогой курс.
- `vw_StudentProgress` — процент завершённых уроков по каждой записи на курс.
- `fn_StudentCourseCount(@StudentID)` — количество курсов студента.
- `fn_LessonsByCourse(@CourseID)` — таблица уроков курса.
- `sp_EnrollStudent(@StudentID, @CourseID)` — записать на курс с проверкой на дубликат.
- `sp_CompleteLesson(@EnrollmentID, @LessonID, @Score)` — отметить урок пройденным с проверкой `Score` от 0 до 100 и что урок ещё не пройден.
- `TR_LessonCompletions_Log` — AFTER INSERT, выводит `SELECT` с информацией о завершении урока.
- `TR_LessonCompletions_Validate` — INSTEAD OF INSERT, запрещает завершить урок, если студент не записан на курс.
- Оконная: `RANK()` студентов по среднему баллу внутри курса.
- Транзакция с `TRY...CATCH`: запись на курс + отметка первого урока; при ошибке — `ROLLBACK`.
- Курсор: курсы, где все уроки пройдены хотя бы одним студентом — `PRINT` название.

## Билет 4. Банк

**Предметная область:** Упрощённый банк. Клиенты, счета в разных валютах, транзакции по счетам (дебет/кредит). Баланс не может быть отрицательным.

**Таблицы (минимум):** `Clients`, `Currencies`, `Accounts`, `Transactions`.

**Обязательные объекты:**
- Запросы: клиенты + сумма балансов (LEFT JOIN + SUM), счета без транзакций (LEFT JOIN + IS NULL), клиенты с более чем 2 счетами (GROUP BY + HAVING), подзапрос — счета с балансом выше среднего.
- `vw_AccountStatement` — все транзакции по счёту с нарастающим итогом.
- `fn_GetBalance(@AccountID)` — текущий баланс счёта.
- `fn_AccountsByClient(@ClientID)` — таблица счетов клиента.
- `sp_TransferMoney(@FromAccountID, @ToAccountID, @Amount)` — перевод с проверкой достаточности средств и транзакцией.
- `sp_OpenAccount(@ClientID, @CurrencyCode)` — открыть счёт с нулевым балансом.
- `TR_Transactions_UpdateBalance` — AFTER INSERT, обновляет `Balance` в `Accounts` в зависимости от типа операции.
- `TR_Transactions_PreventNegative` — INSTEAD OF INSERT, запрещает дебет, приводящий к отрицательному балансу.
- Оконная: `ROW_NUMBER()` счетов по балансу внутри клиента.
- Транзакция с `TRY...CATCH`: перевод денег; при ошибке на втором шаге — `ROLLBACK`.
- Курсор: клиенты с суммарным балансом > 1 000 000 — `PRINT` предупреждение.

## Билет 5. Автосервис

**Предметная область:** Автосервис принимает автомобили на ремонт. У клиента может быть несколько автомобилей. Ремонт состоит из работ (услуг), у каждой работы есть цена и исполнитель (мастер).

**Таблицы (минимум):** `Clients`, `Cars`, `Masters`, `Services`, `RepairOrders`, `RepairItems`.

**Обязательные объекты:**
- Запросы: клиенты + автомобили (JOIN), клиенты без ремонтов (LEFT JOIN), мастера с числом работ (GROUP BY + HAVING), подзапрос — работы дороже средней цены.
- `vw_RepairTotals` — суммарная стоимость каждого ремонта.
- `fn_ClientRepairCount(@ClientID)` — количество ремонтов клиента.
- `fn_ServicesByMaster(@MasterID)` — таблица работ мастера.
- `sp_CreateRepair(@ClientID, @CarID)` — создать заказ на ремонт со статусом `New`.
- `sp_AddRepairItem(@RepairOrderID, @ServiceID, @Quantity)` — добавить работу с проверкой положительного количества.
- `TR_RepairItems_Log` — AFTER INSERT, выводит `SELECT` с информацией о добавленной работе.
- `TR_RepairOrders_PreventCloseWithItems` — INSTEAD OF UPDATE, запрещает закрыть ремонт (`Status = 'Closed'`), если в нём нет ни одной работы.
- Оконная: `RANK()` мастеров по суммарной стоимости выполненных работ.
- Транзакция с `TRY...CATCH`: создание ремонта + добавление первой работы; при ошибке — `ROLLBACK`.
- Курсор: мастера с более чем 5 работами — `PRINT` имя.

- `fn_DriverTripsCount(@DriverID)` — число поездок водителя.
- `fn_TripsByDriver(@DriverID)` — таблица поездок водителя.
- `sp_CreateTrip(@ClientID, @DriverID, @Distance)` — создать поездку со стоимостью = расстояние × тариф (тариф — константа, например 50).
- `sp_CompleteTrip(@TripID)` — завершить поездку (статус `Completed`), если она ещё не завершена.
- `TR_Trips_Log` — AFTER UPDATE, при завершении поездки выводит `SELECT` с информацией.
- `TR_Trips_PreventBusyDriver` — INSTEAD OF INSERT, запрещает назначить водителя, у которого есть активная поездка.
- Оконная: `RANK()` водителей по числу завершённых поездок.
- Транзакция с `TRY...CATCH`: создание поездки + завершение; при ошибке — `ROLLBACK`.
- Курсор: водители с более чем 3 активными поездками — `PRINT` имя.

## Билет 14. Школа

**Предметная область:** Школа ведёт учёт учеников, классов и учителей. Учителя ведут предметы в классах, ученики получают оценки.

**Таблицы (минимум):** `Teachers`, `Subjects`, `Classes`, `Students`, `Grades`.

**Обязательные объекты:**
- Запросы: ученики + классы (JOIN), учителя без предметов (LEFT JOIN), классы с числом учеников (GROUP BY + HAVING), подзапрос — ученики со средней оценкой выше средней по школе.
- `vw_StudentAverageGrade` — средняя оценка по каждому ученику.
- `fn_StudentAverage(@StudentID)` — средняя оценка ученика.
- `fn_StudentsByClass(@ClassID)` — таблица учеников класса.
- `sp_AddGrade(@StudentID, @SubjectID, @TeacherID, @Grade)` — добавить оценку с проверкой, что оценка от 1 до 5.
- `sp_TransferStudent(@StudentID, @NewClassID)` — перевести ученика в другой класс.
- `TR_Grades_Log` — AFTER INSERT, выводит `SELECT` с информацией о выставленной оценке.
- `TR_Grades_PreventBadGrade` — INSTEAD OF INSERT, запрещает ставить оценку ниже 2 (допустим, политика школы).
- Оконная: `RANK()` учеников по средней оценке внутри класса.
- Транзакция с `TRY...CATCH`: добавление оценки + логирование; при ошибке — `ROLLBACK`.
- Курсор: ученики со средней оценкой ниже 3 — `PRINT` имя.

## Билет 15. Авиакомпания

**Предметная область:** Авиакомпания выполняет рейсы. У рейса есть самолёт, пункт назначения и дата. Пассажиры покупают билеты на рейсы.

**Таблицы (минимум):** `Aircrafts`, `Flights`, `Passengers`, `Tickets`.

**Обязательные объекты:**
- Запросы: рейсы + самолёты (JOIN), самолёты без рейсов (LEFT JOIN), пункты назначения с числом рейсов (GROUP BY + HAVING), подзапрос — рейсы с числом билетов выше среднего.
- `vw_FlightLoad` — число проданных билетов и загрузка рейса (в процентах от вместимости самолёта).
- `fn_FlightTicketsCount(@FlightID)` — число билетов на рейс.
- `fn_FlightsByDestination(@Destination)` — таблица рейсов в пункт назначения.
- `sp_CreateFlight(@AircraftID, @Destination, @FlightDate)` — создать рейс.
- `sp_SellTicket(@FlightID, @PassengerID, @SeatNumber)` — продать билет с проверкой, что место не занято и вместимость не превышена.
- `TR_Tickets_Log` — AFTER INSERT, выводит `SELECT` с информацией о проданном билете.
- `TR_Tickets_PreventOverbooking` — INSTEAD OF INSERT, запрещает продажу сверх вместимости самолёта.
- Оконная: `RANK()` рейсов по числу проданных билетов.
- Транзакция с `TRY...CATCH`: продажа билета + логирование; при ошибке — `ROLLBACK`.
- Курсор: рейсы с загрузкой менее 50% — `PRINT` информация.
